# Decision records

A decision record captures one technical choice that has already settled: the constraint that forced it, what was chosen, which alternatives lost and why, and what the choice now ties or blocks. It exists so a later reader does not have to reconstruct the reasoning from commit messages. Records are not edited to match later code; a reversal gets a new record.

Security records are joined into one picture in [`../threat-model.md`](../threat-model.md): every API route, the secrets it may touch, and the record that governs it. A new security record should also update that page.

An accepted risk expires. A record whose title starts `ACCEPTED RISK`, or any record that accepts a risk under another title, carries two lines in its consequences: `**Revisit by:** YYYY-MM-DD`, at most a year out, and `**Re-decided by:**`, naming who decides again. A reopen trigger alone depends on someone noticing that it fired; the date asks again even if nobody does. `src/lib/acceptedRiskRevisit.test.ts` fails when a record titled `ACCEPTED RISK` lacks either line, when a date is malformed or more than a year out, and from the revisit date onwards. To re-decide, write a new record or add a dated status line with a new revisit date.

A record that constrains specific code names it on a `**Governs:**` line directly under its title: the repo paths, each in backticks, that an agent could break the decision by editing. When a governed path sits under a folder with a scoped `CLAUDE.md` pointer, that pointer cites the record, because the pointer is what Claude Code loads when an agent works in the folder. `src/lib/decisionGoverns.test.ts` fails when a governed path no longer exists or the folder's pointer does not cite the record. A warning from `scripts/check-ai-change.mjs` when a commit touches a governed path would close the loop at review time; that is a gate-script edit and is left to the owner.
