# Internationalization (14 locales)
> A typed 14-locale UI translation bundle (`en.ts` is the source of truth) with a `useTranslation` hook and a Zustand locale store. · **Route:** n/a (lib) · **Status:** Live (bundle present; the per-locale release list ships EMPTY, so production stays English-only until the owner releases a locale; `NEXT_PUBLIC_SHOW_LANGUAGE_SWITCHER=true` previews all 14)

## What it does
Provides every user-facing string from a single typed bundle so the UI can be localized into 14 languages: `en` plus `ar, bn, cs, de, es, fr, hi, id, ja, ko, ru, vi, zh`. Components read strings through `useTranslation()` (`t.namespace.key`) instead of hardcoding English. English (`en.ts`) is the typed source of truth; the other 13 locales mirror its shape and are merged over English with per-field fallback. The full machinery — lazy per-locale loaders, English-fallback merge, persisted store, a footer `LanguageSwitcher`, a browser-language offer and a `?lang=` deep link — is shipped. **Which locales a visitor can reach is a per-locale release list** (`LOCALE_RELEASE`, `src/i18n/localeRelease.ts`), and it ships empty: until the owner adds a locale, `setLanguage` refuses every non-en code, the switcher renders `null`, the offer never mounts, and a persisted locale is scrubbed back to `en`. `NEXT_PUBLIC_SHOW_LANGUAGE_SWITCHER=true` (dev/QA/preview) is the preview override that makes all 14 reachable. **Releasing a locale today still leaves the owner-approved English-only pending copy (`src/i18n/pending/`: `/`, `/features`, `/how`, `/m`, the phone dashboard) in English on those routes.**

## How it works
- `useTranslation()` (`src/i18n/useTranslation.ts:15`) is a `useSyncExternalStore` selector over the one catalog store, `catalog` (`src/i18n/catalog.ts:241`), and returns `{ t, language }` (the API every consumer reads is unchanged). Its effect calls `catalog.activate(language)`; the server snapshot is `getServerCatalog()`, always English (`catalog.ts:211`), so the hydrating render matches the static HTML whatever locale a returning visitor persisted.
- The store (`createCatalogStore`, `catalog.ts:82`) memoises one merged catalog per (language, registry version), so all callers share one object and re-render only when the catalog changes. `loadLocale` (`catalog.ts:157`) imports `./<lang>` once per locale (an in-flight promise cache: one load and one merge however many components ask), merges it over the English core with `deepMerge` (`catalog.ts:65`) for per-field fallback, and loads the locale part of every registered section. `activate` (`catalog.ts:188`) keeps the prior locale visible until the requested one resolves rather than flashing English.
- **Catalog sections.** `en.ts` carries the CORE only (`CoreTranslations = Omit<Translations, SectionNamespace>`, `en.ts:1950-1953`); route-owned namespaces live in `src/i18n/sections/`. A section module (`sections/<name>.ts`) holds its English part (`sections/en/<name>.ts`) and one loader per non-en locale (`sections/<lang>/<name>.ts`), and joins the catalog through `registerSection` (`catalog.ts:176`), called at MODULE SCOPE by the module that loads the section's readers. Until a section's locale part arrives it reads English, field by field. Two sections today: `athenaPage` (registered in `src/components/sections/athena-lazy.tsx`, so `/athena` and the dev-only `/preview` both get it) and `legal` = `legalPage` + `cookiePolicy` + `privacyPolicy` (registered in `src/app/legal/LegalContent.tsx`).
- **Per-locale release (2026-10-10).** `src/i18n/localeRelease.ts` is the one predicate every language door derives from. It holds the `LANGUAGES` registry (re-exported by the store), `LOCALE_RELEASE` (`localeRelease.ts:61`; data, one `{ id, since }` per released locale; empty), `LOCALE_PREVIEW` (the env override) and pure functions: `reachableLocales` (en + released, in LANGUAGES order; all 14 under preview), `normalizePersisted` (the rehydration scrub), `negotiateLocale` (`navigator.languages` against the reachable set: `de-AT` -> `de`; English first -> no offer; `zh-TW` / `zh-HK` / `zh-MO` / `zh-Hant` never -> `zh`, which is Simplified), `shouldOffer` (never once declined, never while a non-en locale is active) and `readLangParam` (`?lang=de`, case-insensitive). Acceptance cases: `localeRelease.test.ts`.
- `useI18nStore` (`src/stores/i18nStore.ts`) is `persist`-wrapped (key `personas-language`) and holds `language` (starts `en`) and `declined` (locales whose offer was dismissed; kept INSIDE the already-registered `personas-language` slice, not a new storage key). `setLanguage` (`i18nStore.ts:86`) refuses any locale `isReachable` rejects; `onRehydrateStorage` (`i18nStore.ts:99`) runs `normalizePersisted`, so withdrawing a locale from the list scrubs every visitor stored on it. `LANGUAGE_SWITCHER_ENABLED` survives as an alias of the preview override.
- **Doors.** `LanguageSwitcher` (footer, `FooterCopyright`) lists only `reachableLocales` and renders `null` for English alone; on focus / pointer-enter it warms the browser's negotiated locale through `catalog.loadLocale` (deduped by the store). `LocaleOffer` is mounted in the root layout through `LocaleOfferMount` (`next/dynamic({ ssr: false })`; while nothing is released it renders nothing and the chunk never loads). It applies a `?lang=` link once through `setLanguage`, and shows one dismissible card when `shouldOffer` holds. Its three strings (`t.localeOffer.prompt/accept/dismiss`) come from the TARGET locale's catalog (`catalog.loadLocale(target)`), so the card speaks the offered language (with `lang`/`dir` set on it) and its load is the one accepting needs. Dismiss appends to `declined`. The card is static (no motion) and sits under the navbar (`top-20`) so it never stacks on the cookie banner. The pre-paint script in `layout.tsx` is unchanged (it still forces `lang=en` before rehydration).
- **Locale fonts load on demand.** `applyLangToDOM` (`i18nStore.ts:63`, run by both `setLanguage` and rehydration) sets `lang`/`data-lang`/`dir` and calls `ensureLocaleFont` (`i18nStore.ts:51`), which appends one Google Fonts `<link id="noto-font-<lang>">` for the locale's Noto family (`NOTO_FAMILY`: SC, JP, KR, Arabic, Devanagari, Bengali); Latin/Cyrillic locales load nothing. The root layout no longer links any Noto stylesheet (it was render-blocking on every page for fonts the English-only site never uses); `styles/typography.css` still maps each `data-lang` to its family.
- Guide content has a parallel, equally-dormant resolution path: `resolveTopicUnit` (`src/data/guide/getLocalized.ts:125`) lazy-loads `src/data/guide/locales/<lang>/…` and serves whole units (a current translation, or the whole current English page; never per-field), gated on the same `language` value. See the related guide docs below.

## Data & state
- **Source:** `en.ts` (source of truth) + 13 mirrored locales merged over English via `deepMerge` (per-field fallback). **Stores:** `i18nStore` (Zustand + `persist` under `personas-language`; `language` + `declined`; `setLanguage` refuses unreleased locales — a constant `en` in production while the release list is empty). **API routes:** none (pure client lib; the only network use is the on-demand Noto stylesheet). **Types:** `Translations` interface in `en.ts` is the compile-time contract (every namespace, sections included); `LocaleTranslations` (= `CoreTranslations`) is what the 13 core locale files and the core loaders are typed against; `Language` union (`localeRelease.ts:19`, re-exported by the store) enumerates the 14 codes and is the key type for the core and section loader maps (`Record<NonEnLanguage, ...>`, so a missing locale fails tsc; `catalog.test.ts` also pins each section's loader keys to `LANGUAGES` minus `en`).

## Integration points
- ~260 `.tsx` files call `useTranslation()` and read `t.<namespace>.<key>`; `tsc` enforces that every accessed key exists on `Translations`.
- The `Language` union is imported by both `useTranslation.ts` and `getLocalized.ts`; adding a locale means extending that union, the `coreLoaders` map in `catalog.ts`, each section's `loaders`, and shipping `src/i18n/<lang>.ts` + `src/i18n/sections/<lang>/*.ts`.
- Translation completeness is a CLAUDE.md non-negotiable (#1): add/rename/delete keys in `en.ts` **and all 13 non-en locales in the same commit**; no English placeholders in non-en files. The one sanctioned exception is English-only pending copy, which lives outside `en.ts` in `src/i18n/pending/` (below).

## Conventions & gotchas
- **Releasing a locale is a one-line data edit.** Add `{ id: "de", since: "<date>" }` to `LOCALE_RELEASE`; the setter, scrub, switcher, offer and `?lang=` all follow. Release condition per locale (owner's call): coverage 100% and encoding clean (both gates hold for all 13 today), a native read of the offer strings and the core UI, and acceptance that the pending English-only landing copy stays English. None is released today, so production is English-only exactly as before. Withdrawing a locale scrubs stored visitors back to `en` on their next load. `NEXT_PUBLIC_SHOW_LANGUAGE_SWITCHER=true` (preview deploys) still opens all 14, including the per-locale Noto font fetch.
- **No per-visitor storage beyond `personas-language`.** `declined` lives inside that slice on purpose: `src/data/storage-register.test.ts` scans all of `src` for storage keys, and a new key would need a register entry and a cookie-policy purpose in 14 locales.
- **Known limit:** a visitor who accepts an offer and later switches back to English through the switcher is offered again on the next load (switching does not mark the locale declined).
- **Pending-translation namespaces (owner decision 2026-09-25, PLAN M4) live in `src/i18n/pending/` (PLAN M22, 2026-10-07).** English-only copy that has not been translated yet does not go in `en.ts`: `en.ts` is imported statically by `useTranslation`, so everything in it ships in every route's first-load JS (the `mobile` + `/m` landing copy alone cost +37-40 KB on every route). Instead each pending namespace is one module, `src/i18n/pending/<namespace>.ts`, holding `export interface <Namespace>Copy` and `export const <namespace>Copy: <Namespace>Copy`. Components import the const directly (`import { mobileCopy } from "@/i18n/pending/mobile"`, then `mobileCopy.notes.nav`), so only the routes that render a namespace bundle it; a direct import also works in server components and `metadata`. No hook: the copy is English-only, so there is nothing for `useTranslation` to switch. The `Copy` suffix is load-bearing: copy:check's extractor reads a `*Copy` const as a dictionary (every string, short labels included); a bare `mobile` const would be read as code and its one-word labels skipped.
  - **To translate a pending namespace:** paste its interface body into `Translations` and its value into `en` (both halves of `en.ts`), translate it in all 13 locale files, delete the module, and point the consumers back at `t.<namespace>` (a mechanical `<namespace>Copy.` → `t.<namespace>.` rewrite plus a `useTranslation()` call where the component has none).
  - **Gates that cover the pending modules:** `check:i18n-coverage` loads every module (it must export `<filename>Copy`), prints the pending key count, and fails if a namespace is both pending and in `en.ts` or a locale file; `check:i18n-encoding` scans them at en.ts's zero tolerance (outside the locale baseline); `copy:check` reads them through the `src/i18n/pending/*.ts` source in `docs/i18n/copy-contract.json`.
  - **The 23 pending modules (2026-10-07):** dashboard `mobile`, `personasMonitor`; `/m` `mobileLanding`, `/m2` `mobileLanding2`; landing and `/features` sections `useCasesPersona`, `teamCanvasSection`, `pricingSection`, `playgroundSection`, `orchestrationSection`, `companionSection`, `visionStack`, `designMatrix`, `memorySection`, `securitySection`, `aiModelsSection`, `observeSection`, `pluginsExtra`, `getStartedSection`, `labSection`, `landingSections`, `featuresSections`; `/athena` `athenaSections`; `/how` `howSections`. The old in-file mechanism (`PENDING_TRANSLATION`, an optional-namespace `LocaleTranslations`, `BEGIN/END` markers) is retired; `check:i18n-coverage` fails if `PENDING_TRANSLATION` comes back.
  - **Measured effect (2026-10-07, production build, first-load uncompressed JS per route, 24 routes):** the floor every route pays fell 953 -> 873 KB (-80 KB); median route 1067 -> 988 KB. Routes that render pending copy keep their own share: `/` -77, `/m` -75, `/how` -71, `/m2` -68, `/dashboard/[view]` -64 (keeps `mobile` + `personasMonitor`; the before figure predates the same day's phone reviews work), `/features` -63 KB. A namespace shared by several sections of one route still costs that route the whole module (`landingSections` on `/` and `/features`).
- **Catalog sections (2026-10-10): translated, route-only copy also leaves the shared chunk.** `en.ts` is imported statically (via `catalog.ts`) wherever `useTranslation` is, i.e. on every route; a namespace read only by one route's files becomes a section instead, keeping its translations.
  - **To add a section:** add its name to `SectionNamespace` (`en.ts`); move its value out of `en.ts` and each locale file into `src/i18n/sections/<lang>/<name>.ts` (`export const <lang>: Pick<Translations, "...">`) with a throwaway script that copies the bytes verbatim (never retype non-ASCII); write `sections/<name>.ts` (`CatalogSection`, one `import()` per locale); call `registerSection(<name>Section)` at module scope in the module that loads every reader (never in render); add the owner folders to `SECTION_OWNERS` in `sectionOwnership.test.ts`.
  - **Gates:** `check:i18n-coverage` compares each section per locale at the same 100%; `check:i18n-encoding` scans `sections/**` and holds every file to zero; `copy:check` reads `src/i18n/sections/en/*.ts` (its baseline was re-fingerprinted as a pure path rename on the move, 542 -> 542). `scripts/i18n/report-identical-values.mjs` does not read sections yet (it under-counts them).
  - **Dead key, kept:** `legalPage` (title/heading/description) has no reader outside `src/i18n`; it moved with the legal section rather than being deleted. Deleting it is a separate change across all 14 locale parts.
  - **Bundle claim, to measure:** every route except `/athena`, `/legal` (and dev-only `/preview`) should lose roughly 25-28 KB uncompressed first-load JS (the four values were 27.8 KB of the 96.5 KB English value); `/athena` and `/legal` should hold roughly level. Re-baseline `bundle-budget.json` from a production build.
- **Non-en files are mojibake on disk.** Per project memory, `src/i18n/*.ts` for the 13 non-en locales are UTF-8+BOM with double-encoded existing values. Do **not** deep-read or byte-verify them; anchor any `Edit` on pure-ASCII keys, write correct UTF-8, and don't attempt to "fix" the corruption in passing. Describe the bundle from `en.ts` + the hook + the store (as this doc does).
- **`en.ts` is one large file, two halves.** Lines `1`–`1931` are the `Translations` interface (the contract); the `en` const literal starts at `en.ts:1955`. Edit both halves together — `tsc` will flag a key added to one but not the other.
- **English fallback is silent.** `deepMerge` overlays a locale onto `en`, so a missing/untranslated key renders English with no warning. This makes partial translations safe but also makes translation gaps invisible at runtime — completeness is enforced only by review + the CLAUDE.md rule, not by tooling.
- **Many sections bypass the bundle.** With ~670 `.tsx` files but only ~260 using `useTranslation`, a large amount of UI text is hardcoded English in JSX/`aria-label`/`alt`/`metadata`. CLAUDE.md forbids new hardcoded strings, but substantial existing copy is not in the bundle and would not localize even if switching were enabled. Treat "everything is translatable" as aspirational, not current reality. (The revamped landing and `/features` sections were migrated on 2026-09-25 into the pending namespaces above; brand/model names and code-like text such as intent ids, event names and file names stay in code on purpose. The `/illustrate` sections — team canvas, get started, pricing, healing, lab — were excluded.)
- **Anti-flicker behavior matters if you re-enable switching.** The loader path deliberately keeps the previous locale on screen until the new one resolves (`catalog.ts:188`, `activate`) rather than flashing English; preserve this when wiring up a switcher.
- **Persistence follows the release list.** The store persists `language` + `declined` under `personas-language`; a persisted locale that is not reachable is discarded on rehydration.
