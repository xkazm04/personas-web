## Rules for every variant (the skill's builder rules, made concrete)

1. Same props as the switcher passes (hero: `{ publicBetaLabel: string }`; vision and
   use-cases: none). Do not edit any file except your own variant file(s). You may add
   small sibling files named `<Section>.<variant>.*.tsx|ts` for sub-components.
2. Tokens: `text-foreground`, `text-muted`, `text-muted-dark`, `border-glass*`,
   `bg-white/[0.0x]` glass, `text-brand-*`, `BRAND_VAR`/`tint` from `@/lib/brand-theme`,
   typography helpers in `@/lib/typography`. No raw hex in JSX except data-driven brand
   colours (connector/persona colours from data). No text opacity below /60.
3. Real nouns only: connectors from `src/data` or the section's own `data.ts`, template
   counts derived the way `src/components/sections/Hero.tsx` derives them. **No
   metric-shaped numbers without a source** (no "12,847 executions", no "94%"). Sample
   values are plausible and obviously sample (e.g. "last run 2 min ago", "$0.04").
4. Resting state is server-rendered and visible: nothing that must be seen starts at
   `opacity: 0` in markup. Use `initial={false}` or plain CSS for resting content; if
   you animate an entrance, arm it on the client after mount and never under reduced
   motion. Read the preference with `useStillMotion` from `@/hooks/useStillMotion`,
   never framer's `useReducedMotion`.
5. Motion: transform/opacity only; plays once when in view; no infinite loop without a
   visible pause control. Mechanism motion (a run progressing, frames developing) is a
   short beat list driven by one progress value, and its reduced-motion form is the
   completed state that still shows the order (stage chips with a time axis, the full
   contact sheet).
6. Text inside illustrations is real DOM/SVG text. Decorative shapes get `aria-hidden`.
   The illustration root gets an accessible label summarising what it shows.
7. Reserve the box (fixed height or aspect ratio) so nothing shifts when it hydrates.
8. Section copy: keep the section's existing heading via the same i18n keys
   (`useTranslation`) where the current version uses them. New microcopy inside the
   illustration may be English literals for the prototype; list them in your report.
9. Quality bar: look at `src/components/sections/team-canvas/variants/AssemblyLine.tsx`
   and `get-started/visuals/*` for this site's polish level, and exceed it.
10. Run `npx tsc --noEmit` (ignore errors under `.next/`) and
    `npx eslint <your files>` before reporting. No git commands.
